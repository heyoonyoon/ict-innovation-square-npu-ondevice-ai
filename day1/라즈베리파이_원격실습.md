# 라즈베리파이 원격 실습 정리

모니터, 키보드, 마우스 없이 맥북 하나로 Raspberry Pi 5(npu-16)를 다루며 C02 객체 탐지 실습을 진행한 방법을 정리한다. 명령은 맥북의 SSH 터미널에서 입력하고, 카메라 영상과 탐지 결과 창은 VNC로 띄운 라즈베리파이 바탕화면에서 확인한다.

## 1. 처음 한 번만 하는 설정

키트는 와이파이가 설정되지 않은 상태로 받았기 때문에 맥북에서 라즈베리파이를 찾을 수 없었다. 그래서 키보드를 잠깐 빌려 라즈베리파이 터미널에서 와이파이 연결과 SSH 활성화를 먼저 했다.

```bash
hostname                       # 키트 이름 확인 (npu-16)
whoami                         # 사용자 이름 확인 (student)
sudo nmcli dev wifi connect "와이파이이름" password "와이파이비밀번호"
sudo systemctl enable --now ssh
sudo raspi-config nonint do_vnc 0
hostname -I                    # IP 확인
```

와이파이와 SSH 설정은 저장되므로 재부팅한 뒤에도 자동으로 연결된다. 다만 IP는 바뀔 수 있으므로 접속할 때는 IP 대신 `npu-16.local` 이름을 쓴다.

## 2. 맥북에서 접속하기

### SSH

맥북 터미널에서 아래 명령으로 접속한다. 처음 접속할 때 나오는 확인 질문에는 `yes`를 입력한다.

```bash
ssh student@npu-16.local
```

### VNC

맥 기본 화면 공유 앱은 라즈베리파이 VNC 서버의 로그인 방식을 지원하지 않아 연결에 실패했다. 그래서 TigerVNC를 설치해 `npu-16.local`로 접속했다.

```bash
brew install --cask tigervnc-viewer
```

### SSH에서 실행한 프로그램의 창을 VNC 화면에 띄우기

SSH 세션은 라즈베리파이 바탕화면이 어디에 있는지 모르기 때문에 그대로 `rpicam-hello`를 실행하면 `Preview window unavailable`이 나온다. 아래 한 줄을 `~/.bashrc`에 넣어 두면 SSH로 접속할 때마다 창이 VNC 바탕화면에 뜬다.

```bash
echo 'export WAYLAND_DISPLAY=wayland-0 XDG_RUNTIME_DIR=/run/user/$(id -u)' >> ~/.bashrc && source ~/.bashrc
```

## 3. C02 객체 탐지 실행

강의에서 제시된 명령은 다음과 같다.

```bash
cd ~/hailo-apps
source setup_env.sh
hailo-detect --input rpi --show-fps
```

모니터 없이 VNC로 실행했을 때는 탐지 프로그램이 약 8 FPS로 돌아 영상이 심하게 끊겼다. 결과 창을 가상 화면에 그리는 작업이 전체 처리 속도를 끌어내린 것으로 보고, 출력 창 크기를 줄이고 화면 동기화를 끄는 옵션을 붙여 해결했다.

```bash
hailo-detect --input rpi --show-fps --width 640 --height 360 --disable-sync
```

| 옵션 | 효과 |
|---|---|
| `--width 640 --height 360` | 결과 창을 작게 그려 화면 출력 부담과 VNC 전송량을 줄인다 |
| `--disable-sync` | 화면 출력 속도를 기다리지 않고 프레임을 처리한다 |

옵션을 붙이면 강의 명령과 조건이 달라지므로 기록표에 사용한 옵션과 원래 명령의 FPS를 함께 적는다.

## 4. 주의할 점

### 전원은 명령으로 끈다

전원 케이블을 바로 뽑으면 SD카드가 손상될 수 있으므로 SSH에서 명령으로 끈 뒤 전원을 분리한다.

```bash
sudo reboot              # 재부팅
sudo shutdown -h now     # 완전히 끄기
```

### 카메라 영상을 맥북으로 직접 보내지 않는다

`rpicam-vid`로 720p 30fps 영상을 맥북에 스트리밍하던 중 라즈베리파이가 네트워크에서 사라지고 응답하지 않아 전원을 다시 연결해야 했다. Raspberry Pi 5에는 영상 압축 전용 칩이 없어 CPU로 압축하므로 부하가 컸던 것으로 추정하지만, 로그가 남지 않아 원인을 확정하지는 못했다. 기본 설정에서는 재부팅하면 로그가 사라지므로, 다음 문제가 생겼을 때 원인을 확인할 수 있도록 아래 명령으로 로그를 저장하게 해 둔다.

```bash
sudo mkdir -p /var/log/journal
sudo systemctl restart systemd-journald
journalctl -b -1 --no-pager | tail -50   # 직전 부팅의 마지막 로그 확인
vcgencmd get_throttled                   # 0x0이 아니면 전압 저하나 과열 이력 있음
```
