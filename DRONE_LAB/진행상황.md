# 드론 경보 온디바이스 AI 프로젝트 진행 상황

이 문서는 대화 세션이 바뀌어도 작업을 이어 갈 수 있도록 남기는 인수인계 기록이다. 2026년 11월 8일 오후 6시 기준이며, 새 세션은 이 문서와 같은 폴더의 `HEF_빌드_가이드.md`를 먼저 읽고 이어서 진행한다.


## 1. 프로젝트 개요

NPU 수업(2026 수도권 ICT 이노베이션스퀘어 인공지능 NPU 과정)의 최종 응용 프로젝트로, 라즈베리파이 5와 AI HAT+(Hailo-8L)로 드론을 찾아 경보를 울리는 시스템을 만든다. 요격이나 공격 기능은 없고 화면 경보만 하며, 강의실에서는 드론을 띄울 수 없으므로 노트북 화면에 드론과 새와 빈 하늘 사진을 띄우고 Pi 카메라로 찍어 판별하는 방식으로 데모한다.

수업에서 배운 흐름(전이학습, ONNX 변환과 검증, Calibration, HEF 컴파일, HailoRT 실행)을 그대로 따르고, 기존 실습 코드를 복사해 꼭 바꿔야 하는 줄만 고치는 것을 원칙으로 한다. 수업에서 하지 않은 작업(예를 들어 Pi에 onnxruntime을 설치해 CPU와 NPU를 비교하는 일)은 하지 않기로 했다.

현재 모델은 ADD 실습의 고양이와 강아지 분류(ResNet18 전이학습)를 드론(drone), 새(bird), 빈 하늘(sky) 3클래스 분류로 바꾼 것이다. 클래스 번호는 ImageFolder 규칙에 따라 알파벳순으로 0 bird, 1 drone, 2 sky다.


## 2. 1차 분류 모델에서 완료한 단계

| 단계 | 파일 | 원본 | 결과 |
|---|---|---|---|
| 데이터 준비 | `b01_prepare_data.py` | 새로 작성 | Hugging Face `athkot/drone-vs-bird-synthetic-10k`(CC BY 4.0, AI 생성 사진)에서 박스를 잘라 클래스별 2,000장 저장 |
| 학습 | `b02_train_drone.py` | ADD `a02_train_catdog.py` | 5 epoch, 맥 GPU(mps), 최고 검증 정확도 96.33% |
| ONNX 변환과 검증 | `b03_export_validate.py` | ADD `a03_export_validate.py` | 입력 `input` [1,3,224,224], 출력 `logits` [1,3], 최대 오차 1.2e-05 |
| Calibration 이미지 | `b04_make_calib.py` | 새로 작성 | `calib/drone`에 100장 |
| 정밀도 분석 | `b04_precision_check.py` | ch08 `precision_analysisEx.py` | FP32 42.6 MiB, INT8 10.7 MiB |
| Calibration 분석 | `b04_calibration_check.py` | ch08 `calibrationEx.py` | 포화 비율 모두 0% |
| HEF 컴파일 | `HEF_빌드_가이드.md` | 수업 Step 9 문서 | `pi/drone_resnet18.hef` 생성 |
| Pi 사진 추론 | `pi/b05_npu_single.py` | c17 `c17_cpu_npu_benchmark.py` | 아래 3절 |
| Pi 실시간 경보 | `pi/b06_npu_alarm.py` | b05 | 아래 3절 |
| 맥 데모 화면 | `b07_make_slideshow.py` | 새로 작성 | 데이터 사진을 2초마다 무작위로 바꿔 보여 주는 브라우저 슬라이드쇼 |

b02와 b03을 실행하기 전에는 ADD 실습과 같이 `output/b02_resnet18_drone_best.pth`를 `input/`으로 복사해야 한다. `b01`은 `pyarrow`가 필요한데 `npu_env`에는 설치되어 있지 않다. 학습 데이터(`data/`)와 모델 파일(pth, onnx, hef)은 용량이 커서 깃허브에 올리지 않으므로 다른 컴퓨터에서는 b01부터 다시 만들어야 한다.


## 3. 라즈베리파이 실행 결과

Pi(`student@npu-16.local`)의 `~/hailo_models/drone`에 HEF와 `b05`, `b06`, 검증 사진 3장(`test/`)을 옮겨 Hailo 칩에서 실행했다. c17 코드에는 CPU 비교나 시간 측정이 없고 사진 한 장의 Top-5만 출력하므로, b05는 이 코드에서 경로와 전처리와 출력 부분만 바꿔 만들었다. 전처리는 짧은 변을 256으로 줄이고 가운데 224×224를 잘라 UINT8 RGB 그대로 넣으며, 정규화는 HEF 안에서 하므로 하지 않는다.

| 입력 | 맥 ONNX(FP32) | Pi NPU(INT8) |
|---|---|---|
| sky 검증 사진 | sky 0.9931 | sky 0.9794 |
| 노트북 화면의 드론 사진을 Pi 카메라로 촬영 | drone 0.9693(원본) | drone 0.9662 |

양자화 때문에 logit 차이가 조금 줄어 확률이 약간 낮아졌지만 1위 클래스는 모두 같았고, 화면을 카메라로 다시 찍은 사진에서도 확률이 거의 그대로여서 카메라 사진을 calib에 섞어 HEF를 다시 만드는 작업은 하지 않기로 했다. 카메라는 imx708(Camera Module 3)이며 `rpicam-still -o test/cam.jpg -t 15000`처럼 대기 시간을 길게 주면 그사이 맥 화면에 사진을 띄울 수 있다.

b06은 Picamera2로 프레임을 계속 받아 b05와 같은 방식으로 추론하고, drone 확률이 0.8 이상인 프레임이 5번 연속 나오면 영상 창에 빨간 테두리와 `DRONE ALERT`를 띄운다. 영상 창이 VNC 화면에 떠야 하므로 SSH가 아니라 VNC 화면 안의 터미널에서 실행하며, 종료는 Ctrl+C 또는 영상 창의 q 키로 한다. `hailortcli run`으로 잰 드론 HEF의 FPS는 아직 기록하지 않았다.


## 4. 다음 목표인 실시간 드론 탐지와 추적

지금의 분류 모델은 사진 전체를 보고 드론인지 아닌지만 판단하므로 드론이 화면 어디에 있는지 알 수 없다. 화면 속 드론에 박스를 치고 드론이 움직이면 박스가 따라가도록 만들기 위해 모델을 탐지 모델(YOLOv8n)로 바꾸기로 했으며, 다음 주에 진행한다.

b01이 쓰는 원본 데이터(`data/raw/*.parquet`)에는 드론과 새의 박스 좌표가 이미 들어 있으므로 데이터를 새로 구할 필요는 없다. HEF도 지금과 같이 Hailo Model Zoo에 등록된 `yolov8n` 설정을 빌리고 모델 파일만 직접 학습한 ONNX로 바꿔 끼우는 방식으로 만든다.

| 단계 | 파일 | 장소 | 내용 |
|---|---|---|---|
| 1 | `c01_prepare_det.py` | 맥 | parquet의 박스를 YOLO 형식(클래스, 중심 x, 중심 y, 너비, 높이)으로 바꿔 `data/drone_det`에 저장하며 클래스는 drone과 bird 두 개 |
| 2 | `c02_train_yolo.py` | 맥 | `ultralytics`를 설치해 mps로 YOLOv8n 학습 |
| 3 | `c03_export.py` | 맥 | 640×640 고정 입력으로 ONNX 변환(opset 11, NMS 제외)하고 calib 사진 100장 준비 |
| 4 | Windows VM | 수업 PC | `hailomz compile yolov8n --ckpt ... --classes 2 --hw-arch hailo8l` |
| 5 | `pi/c06_npu_track.py` | Pi | 카메라 프레임을 탐지하고 박스와 추적 번호와 이동 경로를 그린 뒤 같은 드론이 일정 시간 이상 잡히면 경보 |

1부터 3단계는 맥에서 미리 끝내 두고 수업 PC에는 ONNX 파일과 calib 폴더만 가져가 4단계 컴파일만 한다. VM에서 가장 오래 걸리는 것은 optimize 단계이므로 수업이 시작되자마자 돌려 두고 그동안 Pi 코드를 준비한다. ONNX에 NMS(겹치는 박스를 하나로 정리하는 단계)를 넣지 않는 이유는 Hailo가 HEF 안에 NMS를 따로 붙여 주기 때문이고, `--classes 2`를 주는 이유는 Model Zoo의 `yolov8n` 설정이 원래 80클래스용이기 때문이다.

추적은 별도 라이브러리 없이 이전 프레임의 박스와 현재 프레임의 박스가 얼마나 겹치는지(IoU)로 같은 물체인지 판단해 같은 번호를 이어 붙이는 방식으로 구현한다. 프레임 사이에 드론이 많이 움직여 번호가 자주 바뀌면 위치 예측(칼만 필터)을 추가한다.

예상되는 한계도 정리해 두었다. 화면에서 너무 작게 보이는 드론은 640 입력에서 잡히지 않고, Python 후처리와 카메라 때문에 전체 속도는 칩의 최대 속도보다 낮으며, 학습 데이터가 AI 생성 사진이라 실제 드론 영상에서는 성능이 떨어질 수 있다. 그래서 데모는 노트북에 드론이 크게 보이는 움직이는 영상을 틀어 놓고 Pi 카메라로 찍는 방식으로 준비한다.


## 5. 남은 일

1. 드론 HEF를 `hailortcli run`으로 실행해 FPS를 기록한다.
2. 4절의 탐지 모델 1부터 3단계를 맥에서 진행한다.
3. 수업 PC에서 탐지 모델 HEF를 컴파일하고 Pi 추적 코드를 작성한다.
4. 데모용 드론 영상을 구하고 빈 하늘과 새와 드론 장면에서 경보가 드론에만 울리는지 확인한다.


## 6. 사용자 작업 방식

한국어 반말로 짧고 직설적으로 답한다. 명령어는 한 번에 치는 단위로 나누고 각 옵션이 무엇인지 설명한다. 사용자가 요청한 것만 하고, 기존 코드를 최대한 재사용해 수정량을 줄이는 것을 가장 중요하게 여긴다. Pi 비밀번호는 사용자가 직접 입력하며, 다른 사람의 키트에는 아무것도 보내지 않는다.
